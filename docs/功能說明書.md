## 開始之前：你只需要改一個檔案

整個專案的設定集中在 **`firmware/staffroom_config.h`** 這一個檔案。

```bash
py -X utf8 tools/apply_config.py --new-key   # 產生一組自己的裝置金鑰
# 編輯 firmware/staffroom_config.h
py -X utf8 tools/apply_config.py             # 產生三端的 config.h
```

`apply_config.py` 會讀那個檔案，產生 6 個檔案：

```
firmware/Door/config.h          firmware/Door/NetworkDefaults.h
firmware/Audio/config.h         firmware/Audio/NetworkDefaults.h
firmware/Matrix/config.h        firmware/Matrix/NetworkDefaults.h
```

**這 6 個是產生物，不要手改**（下次執行會被蓋掉，舊的會存成 `.bak`）。
本說明書後面提到「設定」時，指的都是 `staffroom_config.h` 裡的那一項。

## 1. 系統組成與資料流

```
   學生                門口機 Door              語音機 Audio            矩陣屏 Matrix
 ┌──────┐          ┌──────────────┐         ┌──────────────┐       ┌──────────┐
 │ 按學號 │ ──觸控─→ │ 7 吋觸控螢幕  │ ─HTTP─→ │ ESP32-S3     │ ─HTTP→│ P5 64×32 │
 │ 選老師 │          │ 無網頁伺服器  │  :80    │ N16R8        │        │ (未交付)  │
 └──────┘          │ 讀 SD 卡名冊  │         │ 讀 SD 卡語音  │       └──────────┘
                   └──────────────┘         │ PCM5102A+喇叭 │
                                            │ 有網頁伺服器 ✅│
                                            └──────────────┘
```

**叫號順序**：`提示音 chime.wav` → `老師 /teachers/<id>.wav` → `學生 /students/<id>.wav`

例：`叮咚` → 「李老師」 → 「5B 陳大文同學找」

### 三個角色的關鍵差異

| | 門口機 Door | 語音機 Audio | 矩陣屏 Matrix |
|---|---|---|---|
| 晶片 | ESP32-S3（Waveshare 7B） | ESP32-S3 N16R8 | ESP32-S3 N32R16 |
| **網頁伺服器** | ❌ **沒有** | ✅ **有（port 80）** | ✅ 有 |
| 螢幕 | 7 吋觸控 1024×600 | 無 | P5 64×32 |
| 記憶卡 | SD_MMC 1-bit | SPI microSD | 無 |
| 記憶卡格式 | 3 欄 | 5 欄 + 語音檔 | — |
| 對外連線 | → Audio | → Matrix（可選） | — |

> **門口機沒有網頁伺服器**是整份文件最重要的一句話。它所有的設定只能在那塊觸控螢幕上做，或由別人（語音機）代替它回報狀態。

## 2. 網路架構

系統**完全不需要網際網路**。所有通訊都是同一個區網內的 **明文 HTTP / TCP 80**。

### 2.1 兩種可行的拓撲

| | **A. 熱點模式**（推薦、最省事） | **B. 學校 Wi-Fi 模式** |
|---|---|---|
| 誰提供網路 | 語音機自己開熱點 | 學校的無線網路 |
| 門口機連到 | `Staffroom-<代號>-Audio` | 同一台 AP |
| 門口機的 Audio 位址 | `192.168.4.1`（固定） | 語音機的區網 IP（會變） |
| 需要設定嗎 | **完全不用，插電即用** | 要在語音機網頁填 SSID／密碼 |
| 距離限制 | 熱點訊號範圍（實測**隔一道牆可用**） | 學校 AP 覆蓋範圍 |
| 學校 Wi-Fi 換密碼 | **不受影響** | 要重填 |
| 矩陣屏 | 也可掛上熱點 | 也可 |

> **兩者不互斥。** 語音機同時開熱點又連學校 Wi-Fi（`WIFI_AP_STA`），所以你可以兩邊都用。

### 2.2 鑑權

每個請求都要帶兩樣東西，缺一不可：

| 位置 | 內容 |
|---|---|
| HTTP 標頭 | `X-Device-Key: <DEVICE_KEY>`（64 位十六進位） |
| JSON 內容 | `"systemId": "<SYSTEM_ID>"` |

`DEVICE_KEY` 三端必須相同。**它就是這套系統的萬用鑰匙**，洩漏等於別人可以任意叫號。

## 3. 熱點（Hotspot）特性 ★

### 3.1 熱點是什麼

語音機自己變成一台 Wi-Fi 基地台。門口機連上去，就不需要學校網路也能叫號。

**參數**

| 項目 | 值 | 備註 |
|---|---|---|
| 熱點名稱 | `Staffroom-<SYSTEM_ID>-Audio` | 例：`Staffroom-ROOM_B-Audio` |
| 熱點密碼 | `DEVICE_KEY` 的**前 12 個字元** | 由程式自動算出，不是另外設的 |
| 熱點 IP | **`192.168.4.1`** | 固定不變，門口機就是打這個位址 |
| 加密 | WPA2-PSK | |
| 頻道 | 1（跟隨 STA 端） | |
| 最大連線數 | **4 台** | 門口機＋矩陣屏＋手機／筆電 |

### 3.2 ⚠️ 熱點是「永遠開著」的（本版的重要改動）

原廠行為是「連不上已存網路滿 60 秒才開，開 10 分鐘就關」。**本版改成開機就開、永不關閉**（`AUDIO_AP_ALWAYS=true`）。

| 行為 | 原廠 v0.3 | **本版** |
|---|---|---|
| 什麼時候開 | 連不上網路滿 60 秒後 | **開機就開** |
| 開多久 | 10 分鐘後自動關 | **永不關閉** |
| 可連幾台 | 1 台 | **4 台** |
| 熱點開著時能叫號嗎 | **不能**（回 `503 network_configuration_active`） | **可以** |
| 從門口機推完設定後 | 熱點自動關 | 熱點繼續開 |

### 3.3 為什麼要這樣改

原本有個**死結**：

> 語音機連在網路 B、門口機連在網路 A → 兩邊永遠碰不到。
> 而熱點「只有在語音機完全沒網路時」才會開——所以它也永遠不會開。

改成常開之後，**熱點永遠在那裡等你**，死結就消失了。

### 3.4 熱點常開的三個後果（必須知道）

**① 校園裡不能有兩台同名熱點 —— 這就是 `SYSTEM_ID` 必須不同的原因**

兩套系統如果都用 `ROOM_A`，校園裡會出現**兩個同名同密碼的熱點**：

```
Staffroom-ROOM_A-Audio   ← 教員室
Staffroom-ROOM_A-Audio   ← 第二間房間   ✗ 分不出來
```

門口機按「改用熱點叫號」時**可能連到隔壁那一台**，第二間房間的叫號會送到第一間的喇叭。

> **每一套系統的 `SYSTEM_ID` 必須不同**（只能用 `0-9 A-Z _ -`，**不能用小寫**，小寫會讓門口機無法開機）。

**② 熱點密碼等於洩漏了 `DEVICE_KEY` 的前 12 碼**

熱點是常開的，方圓內任何人只要知道那 12 碼就能連進來。連進來**不足以叫號**（那要完整 64 碼），但可以嘗試登入網頁控制台。

> **建議**：知道熱點密碼的人不要太多；控制台 PIN 要與熱點密碼不同。

**③ AP 與 STA 共用同一個 2.4 GHz 無線電**

同時開會分掉吞吐。對本系統（幾百 bytes 的 JSON ＋ 從記憶卡播聲音）**完全沒有影響**。

### 3.5 其他網路行為

| 行為 | 值 |
|---|---|
| 斷線後重連間隔（語音機） | **每 10 秒** |
| 斷線後重連間隔（門口機） | **每 10 秒** |
| mDNS 名稱 | `sr-audio-<system_id 小寫>.local`，例 `sr-audio-room_b.local` |
| mDNS 服務 | `_sr-audio._tcp` |
| 協定 | 明文 HTTP，TCP 80 |

> mDNS 讓你在同一個區網不用記 IP，直接開 `http://sr-audio-room_vp.local/`。**但很多學校網路會封鎖 mDNS 廣播**，不通就用 IP。

## 4. 語音機（Audio）網頁控制台 ★

語音機內建一個網頁控制台，**不需要電腦、不需要安裝任何軟體**。

### 4.1 怎麼連線

| 情境 | 你人在哪 | 開這個網址 | 備註 |
|---|---|---|---|
| **A. 手機連熱點**（最常用） | 手機 Wi-Fi 連上 `Staffroom-<代號>-Audio` | **`http://192.168.4.1/`** | 密碼 = `DEVICE_KEY` 前 12 碼 |
| **B. 電腦在同一個區網** | 和語音機同一個 Wi-Fi | `http://<語音機IP>/` | IP 在語音機的「本機 IP」欄位 |
| **C. mDNS** | 同上 | `http://sr-audio-<代號>.local/` | 學校網路常封鎖 |

> ⚠️ **只有情境 A 可以修改 Wi-Fi 設定。** 從區網（情境 B）登入可以看狀態、叫號，但按下「套用網路」會被拒絕（回 `403 setup_ap_required`）。這是刻意設計，防止別人從學校網路把板子改走。

### 4.2 登入

1. 畫面出現「管理員 PIN」
2. 輸入你在 `firmware/staffroom_config.h` 裡設的 `CONSOLE_PIN`
3. 通過後取得一組 **32 位工作階段權杖，有效 30 分鐘**

| 安全設計 | 說明 |
|---|---|
| 網頁本身**不含任何機密** | 任何人抓得到 HTML 也沒用 |
| 密碼錯誤 5 次 | **鎖定 60 秒** |
| 工作階段 30 分鐘到期 | 自動踢回登入頁 |
| 同時只有一組權杖 | 第二個人登入會把第一個人踢掉 |
| 原有的 64 位 `DEVICE_KEY` | **仍然有效**，門口機與電腦工具不受影響 |

### 4.3 主畫面功能

**即時狀態面板**（每 3 秒自動更新）

| 欄位 | 意思 |
|---|---|
| 狀態 | 系統就緒 / 異常 |
| 錯誤 | 開機時的錯誤原因（例如 `sd_mount_failed`） |
| 本機 IP | **語音機在學校 Wi-Fi 的 IP**。這裡是判斷連線的主要依據 |
| Wi-Fi / 訊號 | 連上的網路名稱與訊號強度 |
| 熱點 | 開 / 關，以及熱點 IP（正常應為開啟 · `192.168.4.1`） |
| 熱點名稱 | `Staffroom-<代號>-Audio` |
| **熱點裝置數** | **目前有幾台連在熱點上。門口機連上時應該是 1** |
| 佇列 | 等待播放的數量、是否正在播音 |
| 網路語音檔 | 熱點語音（0–9、dot、ip）是否齊全 |
| 可用記憶體 / bootId | 診斷用 |

**四顆按鈕**

| 按鈕 | 作用 |
|---|---|
| **朗讀本機 IP** | 語音機用喇叭念出自己的 IP（例如「一九二點一六八點四點一」）。**排錯時最好用的一顆** |
| **測試叫號 12345 / 601** | 用固定測試資料發一次叫號，確認整條鏈路 |
| **暫停輪詢** | 停止自動更新，方便截圖 |
| **顯示完整 JSON** | 把 `/diag` 原始內容印出來 |

**最近叫號表**：時間、學號、老師、狀態、**來自哪個 IP**

> **「來自」欄就是門口機的 IP**。因為門口機沒有網頁，這是**唯一能遠端看到門口機的窗口**。看到 `192.168.4.x` 表示門口機走熱點；看到學校網路的 `192.168.x.x` 表示走學校網路。

### 4.4 修改 Wi-Fi 設定 ★

在主畫面下方的「**網路設定**」區塊。

**怎麼填**

| 欄位 | 說明 |
|---|---|
| 加密方式 | **一般 Wi-Fi（WPA2 個人／開放）** ← 家用、手機熱點 |
| | **企業網路 PEAP** ← **學校這種** |
| | **企業網路 TTLS** |
| Wi-Fi 名稱 (SSID) | 例如 `MySchool-WiFi` |
| 帳號 / 身分 | 只有企業網路才出現。學校帳號例如 `s1234567`。身分留空 = 沿用帳號 |
| 密碼 | **每次都要重打**（板子刻意不外洩已存的密碼） |
| Matrix 螢幕 IP | 沒有矩陣屏就留空 |

**按下「套用並讓 Audio 重連」之後**

1. 設定寫入語音機的快閃記憶體（NVS）
2. 約 1 秒後語音機開始連新網路
3. **熱點不會關閉**
4. 連上後，「本機 IP」會變成新位址

> **為什麼改錯不會出事**：因為熱點永遠開著。就算 SSID 或密碼打錯，你只要**重新整理這一頁**就能再改一次，不會把板子變成孤兒。
> （原廠版本熱點 10 分鐘後會關，那時這個功能會是個單向陷阱。）

**限制**

| 限制 | 原因 |
|---|---|
| 只能從熱點改 | 防止區網上的其他人把板子改走 |
| 板子正在播音／排隊時不能改 | 回 `409 audio_busy`，等空閒再試 |
| 企業網路一定要填帳號＋密碼 | 否則回 `422 invalid_network_or_ca_missing` |

> 本系統已設 `ALLOW_INSECURE_EAP=true`，所以**沒有 CA 憑證的學校網路也能連**。

### 4.5 常見錯誤

| 畫面顯示 | 意思 | 怎麼辦 |
|---|---|---|
| `locked` | PIN 錯太多次 | 等 60 秒 |
| `bad_pin` | PIN 不對 | 由 `CONSOLE_PIN` 決定 |
| `unauthorized` | 工作階段到期 | 重新輸入 PIN |
| `setup_ap_required` | 你不是從熱點進來的 | 改連熱點後開 `192.168.4.1` |
| `audio_busy` | 正在播音 | 等它播完 |
| `invalid_network_or_ca_missing` | 欄位不合法 | 企業網路要帳號＋密碼 |
| 一直停在登入頁 | 網路不通 | 確認手機真的連上熱點 |

## 5. 門口機（Door）聯網功能 ★

### 5.1 門口機沒有網頁

**它沒有網頁伺服器，沒有任何遠端介面。** 全部設定都在那塊觸控螢幕上。想知道門口機的狀態，只能：

1. **看它的螢幕**（本機 IP 那一行會自動更新）
2. **看語音機網頁的「熱點裝置數」**（1 = 門口機連著）
3. **看語音機網頁叫號表的「來自」欄**（= 門口機的 IP）

### 5.2 怎麼進入網路設定

螢幕上有顆不顯眼的按鈕：**「網絡設定」**。

點下去會先要 **管理 PIN**（就是 `NETWORK_ADMIN_PIN` 那一項）。

| 逾時 | 值 |
|---|---|
| 網路設定頁閒置 | **180 秒**後自動關閉回主畫面 |
| PIN 輸入頁閒置 | **20 秒** |
| 一般輸入頁閒置 | **60 秒** |
| 完成頁顯示 | 5 秒 |

> 設計用意：**不要讓管理頁留在螢幕上給學生亂按**。

### 5.3 網路設定頁的功能

**第一排：憑證（可看可改）**

| 項目 | 說明 |
|---|---|
| Wi-Fi 名稱 / 密碼 | 用 QWERTY 螢幕鍵盤輸入 |
| 認證方式 | 一般 / 企業 PEAP / 企業 TTLS |

**第二排：四顆按鈕**

| 按鈕 | 作用 |
|---|---|
| **測試 Audio** | 立刻試打一次語音機 |
| **自動尋找 Audio** | 在目前網段搜尋語音機 |
| **朗讀 Audio IP** | 叫語音機用喇叭念出自己的 IP |
| **改用熱點叫號** | **一鍵切到熱點模式**（見下） |

**「改用熱點叫號」做了什麼**（一鍵完成）

1. Wi-Fi 名稱 → `Staffroom-<代號>-Audio`
2. 密碼 → 自動取 `DEVICE_KEY` 前 12 碼（與語音機熱點同源，不會打錯）
3. 認證方式 → 一般／開放
4. Audio IP → `192.168.4.1`
5. 存檔並立刻重連

> 已經在熱點上時，這顆按鈕會變灰並顯示「**已在 Audio 熱點**」，按下去只會提示你怎麼回正式 Wi-Fi，不會亂切。

> **它與「連 Audio 配置熱點」不同**：後者會進入 pairing 狀態（畫面上明寫「不可叫號」），是拿來推設定的臨時模式。本系統的熱點是常開的，所以需要這顆按鈕把熱點當成正式叫號網路。

### 5.4 ⚠️ 一個畫面陷阱

網路設定頁有一行**紅字**：

```
等待 Audio 熱點取得 192.168.4.x
```

**這是死文本，永遠不會更新。** 不要盯著它看。

**真正該看的是畫面頂部的「本機 IP」那一行**，它會在 IP 或狀態改變時自動刷新：

| 顯示 | 意思 |
|---|---|
| `未連線` | 沒連上任何網路 |
| `192.168.4.x` | ✅ 連上語音機熱點（推薦狀態） |
| `192.168.x.x` | 連上學校 Wi-Fi |

## 6. 通訊協定（維護者參考）

### 6.1 端點一覽（語音機，port 80）

| 方法 | 路徑 | 鑑權 | 作用 |
|---|---|---|---|
| GET | `/` | ❌ 公開 | 網頁控制台（純靜態，不含機密） |
| POST | `/console-unlock` | ❌ | 用 PIN 換 30 分鐘權杖 |
| GET | `/health` | ✅ | 精簡狀態 |
| GET | `/diag` | ✅ | 完整診斷（含最近 16 筆叫號） |
| POST | `/announce` | ✅ | **叫號** |
| POST | `/say-ip` | ✅ | 用喇叭念出自己的 IP |
| POST | `/network` | ✅ **＋必須來自熱點** | 修改 Wi-Fi 設定 |
| GET | `/status?requestId=` | ✅ | 查詢某次叫號的結果 |

### 6.2 `/announce` 的錯誤碼

| HTTP | 錯誤 | 意思 |
|---|---|---|
| 400 | `invalid_json` / `invalid_id` | 格式錯，或學號不是 5 位數字 |
| 403 | `unauthorized` / `wrong_system` | 金鑰或系統代號不對 |
| 404 | `id_not_found` | 名冊裡沒有這個學號 |
| 409 | `audio_restarted` | **`expectedBootId` 與實際不符**（板子重開過） |
| 409 | `request_conflict` | 同一個 requestId 但內容不同 |
| 422 | `wav_missing_or_invalid` | 語音檔不存在或格式不合格 |
| 429 | `queue_full` | 佇列滿了（容量 8） |
| 429 | `cooldown_30s` | 同一位學生＋同一位老師 30 秒內重複叫號 |
| 429 | `history_full_retry_later` | 歷史記錄滿了（128 筆 / 10 分鐘） |
| 503 | `audio_not_ready` | 記憶卡或名冊有問題 |
| 503 | `network_configuration_active` | 正在套用網路設定 |

> **`expectedBootId` 很重要**：門口機必須先讀 `/health` 拿到 `bootId`，再帶著它發 `/announce`。如果語音機中途重開，這個值會變，叫號會被擋下（`409 audio_restarted`），避免「按了但其實沒播」。

### 6.3 系統限制

| 項目 | 值 |
|---|---|
| 佇列容量 | 8 |
| 歷史記錄 | 128 筆 / 10 分鐘 |
| 同學生＋同老師冷卻 | 30 秒 |
| 學號格式 | **剛好 5 位數字**（或 `E` + 5 位數字） |
| 老師編號格式 | 1–24 字元，`0-9 A-Z a-z _ -` |
| 請求編號格式 | 同上 |

## 7. 語音與記憶卡

### 7.1 語音檔格式（固件硬性規定）

| 規則 | 值 |
|---|---|
| 容器 | RIFF / WAVE |
| 編碼 | **PCM**（format = 1） |
| 位元深度 | **16-bit** |
| 聲道 | 單聲道或雙聲道 |
| 取樣率 | **只能是 16000 或 22050 Hz** |
| 長度 | **最長 30 秒** |

> **不符合的檔案會被直接拒絕**（回 `422 wav_missing_or_invalid`），而且**不會有任何聲音**。這是最常見的「叫號沒聲音」原因。

### 7.2 兩張記憶卡的分工

**門口機卡（3 欄）**

```
students.csv    studentId,class,maskedName          ← 第 3 欄是顯示用的名字
teachers.csv    teacherId,displayName
```

**語音機卡（5 欄 ＋ 目錄）**

```
students.csv    studentId,class,maskedName,displayName,audioFile
teachers.csv    teacherId,displayName,audioFile
chime.wav                       提示音
students/<學號>.wav              學生錄音
teachers/<老師編號>.wav          老師錄音
network/0.wav … 9.wav, dot.wav, ip.wav   念 IP 用的數字
```

> **兩張卡的格式不能互換。** CSV 一定要在**根目錄**，不要放進子資料夾。
> CSV 用 **UTF-8 無 BOM、CRLF** 換行。

### 7.3 名字顯示

門口機用的是**點陣字型**，字必須事先「烘」進固件（`glyphs.h`）。

> **新增任何名字之後，必須重新產生字型並重新燒錄門口機**，否則那些字會顯示成空白或方框。
> 字庫目前包含的是一個示範名冊；換成你的名冊之後一定要重跑 `tools/generate_fonts.py`。

**名字不做遮罩**，一律顯示全名（例：`陳大文`，不是 `張○凝`）。

## 8. 叫號流程

```
學生                 門口機                     語音機
 │  ① 輸入 5 位學號    │                          │
 │ ─────────────────→ │                          │
 │  ② 從螢幕選老師      │                          │
 │ ─────────────────→ │                          │
 │                     │  ③ GET /health（拿 bootId）│
 │                     │ ───────────────────────→ │
 │                     │  ④ POST /announce         │
 │                     │ ───────────────────────→ │  檢查金鑰、系統代號、bootId、
 │                     │                          │  名冊、WAV 格式、冷卻、容量
 │                     │  ⑤ 200 / 佇列位置          │
 │                     │ ←─────────────────────── │
 │  ⑥ 完成畫面          │                          │  ⑦ 播 chime → 老師 → 學生
 │ ←────────────────── │                          │
```

**重要特性**

- 播放**不會**卡住 HTTP：實測播音 10 秒期間仍可正常回應 36 次查詢
- 矩陣屏離線時，門口機會先花約 **3 秒**重試（`display=failed` 是正常現象，**不是**叫號失敗）
  - 本版交付**已將 `MATRIX_HOST` 設為空白**，沒有矩陣屏也不會拖慢
- 同一個 requestId 重送是**安全的**（會回傳原本的結果，不會重播）

## 9. 重要限制與已知事項

| 項目 | 狀態 |
|---|---|
| 矩陣顯示屏 | **本版未交付**。要加裝時需另燒固件並改 `MATRIX_HOST` |
| 歡迎語 | 需要矩陣屏；沒接矩陣屏時只在門口機上顯示 |
| 學生姓名讀音 | **尚未有人逐班聽過**做人工覆核。格式正確 ≠ 讀音正確 |
| 錄音音色不一致 | 不同批次或不同工具產生的 WAV，聽起來會有差異 |
| 通訊加密 | **明文 HTTP**。同一個區網內可被嗅探（設備金鑰亦然） |
| 熱點密碼 | 等於 `DEVICE_KEY` 前 12 碼，且熱點常開 |
| `SYSTEM_ID` | 只能用 `0-9 A-Z _ -`，**小寫會讓門口機無法開機** |
| 修改 `SYSTEM_ID` / `DEVICE_KEY` | 必須**重新燒錄所有裝置**，不能只改一台 |
| 沒有網頁伺服器的裝置 | 門口機、矩陣屏——它們的狀態只能間接得知 |

## 10. 快速故障排除

| 症狀 | 先查這個 | 通常原因 |
|---|---|---|
| 門口機顯示「未連線」 | 語音機網頁的「熱點裝置數」 | 語音機沒電／熱點沒開。在門口機按「改用熱點叫號」 |
| 叫號有畫面、**沒聲音** | 語音機網頁的「狀態」「網路語音檔」 | WAV 格式不符（必須 PCM16 / 16000或22050Hz）、記憶卡沒插好、喇叭線 |
| 回 `id_not_found` | `students.csv` 是否在卡片根目錄 | 名冊沒複製，或學號不在名單 |
| 回 `wav_missing_or_invalid` | 對應的 `.wav` 是否存在且格式正確 | 最常見原因，見 §7.1 |
| 回 `409 audio_restarted` | 語音機重開過 | 門口機會自動重試；持續發生表示語音機一直重啟 |
| 網頁打不開 `192.168.4.1` | 手機的 Wi-Fi 是否停用「自動切換行動網路」 | 手機偷偷跳回 4G |
| 網頁能開但不能改 Wi-Fi | 你是不是從區網進來的 | 只有從熱點進來才能改（`403 setup_ap_required`） |
| 登入頁進不去 | PIN 錯 5 次被鎖 | 等 60 秒 |
| 改完 Wi-Fi 後連不上 | 熱點還在，重新整理頁面 | 重填一次。**不會失聯** |
| 門口機名字顯示方框 | 字型沒有那個字 | 重產 `glyphs.h` 並重燒門口機 |
| 兩套系統互相干擾 | `SYSTEM_ID` 是否重複 | **必須不同**，見 §3.4 |
